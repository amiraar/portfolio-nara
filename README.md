# Nara — Portfolio + Kaia Chat Assistant

Personal portfolio of **Mohammad Amirul Kurniawan Putranto**, a backend developer in Yogyakarta, Indonesia.
Besides the usual portfolio sections, the site has **Kaia**, an AI chat assistant that answers visitors'
questions about my work. I can join any conversation live from a private dashboard, where I also edit all the
portfolio content without touching code.

**Stack:** Next.js 16 (App Router) · React 19 · Tailwind CSS · Prisma + PostgreSQL (Neon) · Pusher Channels ·
Google Gemini · Vitest · Vercel

---

## Features

### Portfolio
- **Sections:** Hero, About, Experience, Projects, Skills, Education and Certificates.
- **Projects:** every card opens a modal, either a full case study (problem, approach, result and screenshots) or an overview with a link to the Figma file or repository.
- **Certificates:** grouped by category and linked from the matching Experience entries. A full-size viewer shows the per-semester lab courses.
- **Education:** a graduation photo gallery with a lightbox.
- **Light/dark theme:** follows the system setting, with a manual toggle.
- **Responsive layout:** checked at phone, tablet and desktop widths.

### Kaia chat assistant
- **Chat widget:** opens from a floating bubble. Visitors enter their name and email to start.
- **AI replies:** generated by Google Gemini, with fallback models and retries if one model is busy.
- **Realtime:** messages and a typing indicator are delivered through Pusher Channels.
- **Sessions:** a returning visitor's conversation is restored.

### Owner dashboard (`/dashboard`)
- **Conversations:**
  - see all conversations in realtime, with 30-second polling as a fallback
  - take over from Kaia, reply manually, hand back to Kaia, and resolve
- **Analytics:** totals for visitors, active conversations and monthly messages, with a chart.
- **Content editor:** edits every portfolio section and Kaia's system prompt. Changes appear on open tabs immediately.

## Architecture

```
Visitor browser                   Owner browser
      │                                 │
      │  HTTP + Pusher Channels         │  HTTP + Pusher Channels
      ▼                                 ▼
┌──────────────────────────────────────────────┐
│        Next.js App Router (Vercel)           │
│  app/          pages + route handlers        │
│  components/   portfolio, chat, dashboard    │
│  lib/          data, AI, realtime helpers    │
└───────┬──────────────────┬──────────────┬────┘
        ▼                  ▼              ▼
 Pusher Channels     Google Gemini   Neon PostgreSQL
   (realtime)        (AI replies)    (via Prisma ORM)
```

**Content model:**
- Each portfolio section is stored as JSON in the `PortfolioContent` table.
- When a section has never been saved, the site falls back to the defaults in [`lib/portfolioDefaults.js`](lib/portfolioDefaults.js).
- Certificates live in [`lib/certificates.js`](lib/certificates.js).
- Photos live in [`public/`](public/).

## Getting started

### Prerequisites
- Node.js 20.9 or newer (CI uses Node 24)
- A PostgreSQL database (a free [Neon](https://neon.tech) project works)
- A Google AI Studio API key ([aistudio.google.com/apikey](https://aistudio.google.com/apikey))
- A [Pusher Channels](https://pusher.com/channels) app

### Setup

```sh
npm install
cp .env.example .env   # then fill in the values; each variable is described in the file
npm run db:push        # create the tables
npm run dev            # http://localhost:3000
```

### Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Start the development server |
| `npm run build` | Generate the Prisma client and build for production |
| `npm start` | Serve the production build |
| `npm test` | Run the Vitest suite once |
| `npm run test:watch` | Run tests in watch mode |
| `npm run db:push` | Sync the Prisma schema to the database |
| `npm run db:generate` | Regenerate the Prisma client |
| `npm run db:studio` | Open Prisma Studio at `localhost:5555` |

## Deployment

Deployed on **Vercel**; no custom server is needed.
1. Import the repository in Vercel.
2. Add the variables from `.env.example`.
3. Deploy.

GitHub Actions runs the test suite on every pull request.
